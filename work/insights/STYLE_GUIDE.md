# 写作规范（参照 OpenAI《The Hugging Face incident and the road ahead》与 Anthropic《Patterns and problems in multiagent systems》）

目标读者是一线研究者。文字要简洁、凝练、专业，读起来像实验室的技术报告，不像 AI 生成的综述。

## 正文规则
1. **结论先行**。每段第一句就是结论；后面最多两句给证据。一段不超过 3 句、约 120 个汉字。
2. **短句，一句一事**。主谓宾，少用长定语。数字直接嵌入句子：「OPD 从 1 篇增至 907 篇」。
3. **标题写事实**。用陈述句或名词短语，12–22 个汉字为宜：「后训练出现第二根支柱」「越狱攻击份额减半」。不用冒号副标题、不用引号造词、不用「从 X 到 Y」套式（除非确有两个端点）。
4. **禁用词**（及同类）：值得注意的是、不难发现、可以看到、这表明、总的来说、一方面…另一方面、范式转移/范式革命、颠覆、重塑、赋能、全面、深度、显著（改给数字）、惊人、爆发式、井喷、大换血、狂飙、「X 化」生造词、凝视、叙事、底层逻辑、抓手、闭环。
5. **不用**：破折号插入语、反问句、排比、感叹、比喻（「慢性病」「泡沫」「战场」）、括号里的长解释。
6. **术语**：首次出现中英并列，如「在线策略蒸馏（OPD）」，之后只用一种。
7. **数字格式**：份额统一写「每万篇 x → y」或「x% → y%」；倍数写「2.3×」；年份写「2026 → 2027」。保留原有数值，不得改动或新造数字。
8. **方法性内容不进正文**：匹配方式（regex、关键词、簇编号）、口径定义、阈值、样本量、剔除规则、稳健性检验细节、数据局限，一律移入该条目的 `note_zh`（脚注，灰色小字，放在全文末尾）。正文只保留理解结论必需的单位。稳健性结论只保留一句「剔除模板化论文后仍成立 / 不再成立」，细节进脚注。

## 输出（保持原 JSON 结构，逐字段改写）
- `title_zh`：章节标题，≤ 16 个汉字，不带冒号副标题。另加 `subtitle_zh`：一句话（≤ 30 字）点题。
- `headline_zh`：2 句以内的章节结论。
- `stats[]`：`label_zh` ≤ 14 字；`value` 保持；`note_zh` ≤ 20 字，方法细节移脚注。
- `insights[]`：`title_zh` 按规则 3；`body_zh` 按规则 1–2（≤ 3 句）；新增可选 `note_zh`（方法与口径脚注，可为空字符串）；`evidence` 原样保留。`tag` 只能是 rising / fading / shift / watch / gap / stable。
- `rising[] / fading[] / microtopics[]`：`name_zh` ≤ 14 字；`note_zh` ≤ 24 字，只写「是什么 / 为什么」，不写方法。
- `frontline_zh / gaps_zh / watchlist_zh`：各 ≤ 6 条，每条 ≤ 50 字，一条一事。
- `rewarded_2026_zh`：≤ 3 句。
- 新增 `notes_zh`：章节级方法脚注列表（如统计口径、剔除规则）。
